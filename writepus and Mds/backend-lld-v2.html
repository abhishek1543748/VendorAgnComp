Revision 2 — corrected & reviewed

Low-Level Design v2 — Vendor-Agnostic Compliance Engine Backend

Scope: everything needed to actually start writing code — tech stack decisions with reasoning, a tool-level architecture, data models, API contract, database schema, module-by-module design for all three lanes, deployment layout, and ready-to-use dummy data sources for each lane.

Changelog vs v1 — this revision closes 8 gaps found in review before implementation started: 1. Added device identity fields (hostname, serial number, model, firmware version) — explicitly required by the PS's PDF report spec, missing from v1's devices table. 2. Deterministic lane now has an explicit command assumption per platform, and falls back to the LLM lane automatically if parse_output fails or returns empty, instead of deciding the lane purely from the fingerprint. 3. Fingerprint regexes now use re.MULTILINE and multi-keyword scoring instead of a single anchored OR-pattern that would under-match. 4. LLM calls are now async (AsyncAnthropic) so they don't block the FastAPI event loop; bulk uploads parse concurrently via asyncio.gather. 5. Corrected the example model string to a real current model (claude-opus-5), not a placeholder. 6. Added a secret-redaction pass before any config text leaves the process for the LLM lane. 7. Correction submission now re-runs the rule engine on affected devices, not just re-normalization — so the findings dashboard actually updates. 8. Added GET /devices, GET /frameworks, explicit CORS config, Jinja2 autoescape, and WeasyPrint's system dependencies in the Dockerfile.

1. Tech stack — the decisions, and why

Layer Choice Why this and not the obvious alternative
API / orchestrator Python 3.11 + FastAPI Async-native, auto-generates OpenAPI (useful for the frontend and for judges), and it's the only ecosystem where the parsing libraries, the LLM tooling, and the network-automation libraries all live together without a language bridge.
Deterministic parsing TextFSM + ntc-templates (via ntc_templates.parse.parse_output) Real, widely-used, actively maintained library (Network to Code) purpose-built for turning vendor CLI output into structured data. Don't hand-roll regex parsing when this exists. Note: templates are keyed by exact (platform, command) pairs, and the raw text passed in must contain only the command's output, not the command itself — this drives module 7.1/7.2 below.
Live device pulls (optional) Netmiko Named in the brief; useful only if demoing against real/virtual gear. Not required for file-upload-driven scoring — treat as stretch, not spine.
LLM fallback Anthropic API (async) + instructor + Pydantic v2 instructor forces the model to return a validated Pydantic object instead of free text you regex out. This is what makes confidence scoring and source-line citation structural instead of hopeful. Use the async client (AsyncAnthropic) so LLM calls don't block FastAPI's event loop.
Data validation / schema Pydantic v2 Same schema definitions double as the normalized data model, the LLM's structured output contract, and the API's request/response models — one source of truth.
Database PostgreSQL 15 Relational because findings, corrections, and few-shot examples are all joined by device/vendor/OS-version — this is not document-shaped data.
ORM / migrations SQLModel + Alembic Keeps Pydantic and DB models from drifting into two parallel schemas. Caveat: SQLModel's Alembic autogenerate can miss some changes — review autogenerated migrations by eye, don't trust them blindly.
Few-shot / correction retrieval Postgres, plain (vendor, os_hint) keyed lookup for the hackathon cut; pgvector as v2 upgrade Start with the keyed lookup — simpler and demoable.
Background jobs FastAPI BackgroundTasks + asyncio.gather for concurrency within a batch; Celery + Redis only if you outgrow it Bulk upload of tens of files doesn't need a broker, but does need the LLM calls to run concurrently rather than serially, or a 20-file bulk upload will visibly crawl in a live demo.
Rule packs YAML files, loaded at startup, hot-reloadable Rules are data, not code — this is the actual point of the architecture.
PDF report WeasyPrint (HTML/CSS → PDF), Jinja2 with autoescape on Faster to make look professional than ReportLab's canvas API. Requires system packages (Pango/Cairo/GDK-Pixbuf) in the Docker image — see §9.
Frontend React + Vite + TypeScript + Tailwind Three screens (upload, findings dashboard, training/correction UI) — no need for Next.js routing/SSR complexity.
Testing pytest + ntc-templates' own test fixtures as parser regression tests Doubles as your dummy data source — see §10.
Containerization Docker Compose (api, postgres, frontend) One command to stand the whole thing up for a demo.

4. Core data models (Pydantic v2)

from pydantic import BaseModel, Field
from typing import Literal
from datetime import datetime

class SourceEvidence(BaseModel):
    raw_line: str                       # the exact original config line
    line_number: int | None = None

class SecurityBaselineField(BaseModel):
    control_area: str                   # e.g. "ssh_version", "telnet_enabled", "password_min_length"
    value: str                          # the normalized value, e.g. "2", "false", "8"
    evidence: SourceEvidence
    confidence: float = Field(ge=0.0, le=1.0)   # 1.0 for deterministic-lane fields
    source_lane: Literal["deterministic", "llm"]

class DeviceIdentity(BaseModel):
    # NEW in v2 — required by the PS's "Device Identification" report section
    hostname: str | None = None
    serial_number: str | None = None
    model: str | None = None
    firmware_version: str | None = None

class NormalizedDeviceConfig(BaseModel):
    device_id: str
    vendor: str
    os_hint: str | None = None
    identity: DeviceIdentity = DeviceIdentity()
    fields: list[SecurityBaselineField]
    parsed_at: datetime

class ComplianceRule(BaseModel):
    control_id: str                     # e.g. "CIS-1.1.4"
    framework: Literal["CIS", "NIST_800_53", "STIG", "ISO_27001"]
    control_area: str                   # must match a SecurityBaselineField.control_area
    expected_value: str
    severity: Literal["low", "medium", "high", "critical"]
    remediation_template: str           # e.g. "ip ssh version 2" — vendor-specific fill-in

class Finding(BaseModel):
    device_id: str
    control_id: str
    status: Literal["pass", "fail", "needs_review"]
    observed_value: str | None
    severity: str
    remediation_cli: str | None
    evidence: SourceEvidence | None

class CorrectionExample(BaseModel):
    vendor: str
    os_hint: str | None
    raw_line: str
    mapped_control_area: str
    mapped_value: str
    corrected_by: str
    created_at: datetime

7. Module-by-module design

7.1 Vendor detection (ingestion/vendor_detect.py)

Pure Python, no AI — fast and cheap since it runs on every upload before any real parsing happens.

import re

FINGERPRINTS = [
    # (vendor, os_hint, [keyword patterns], ntc_platform, assumed_command)
    ("cisco", "ios", [r"^Building configuration", r"^version \d+\.\d+", r"^service password-encryption"],
     "cisco_ios", "show running-config"),
    ("juniper", "junos", [r"^system \{", r"^## Last commit:"],
     "juniper_junos", "show configuration"),
    ("paloalto", "panos", [r"<config version=", r"^set (deviceconfig|network|rulebase)"],
     None, None),   # no ntc-templates match → LLM lane by design
    ("fortinet", "fortios", [r"^config (system|firewall) "],
     None, None),
    ("sonic", None, [r'"DEVICE_METADATA"\s*:\s*\{'],
     None, None),
    ("mikrotik", "routeros", [r"^/interface", r"^/ip address"],
     None, None),
]

def detect(raw_text: str):
    best = None
    for vendor, os_hint, patterns, platform, command in FINGERPRINTS:
        hits = sum(1 for p in patterns if re.search(p, raw_text, re.MULTILINE))
        score = hits / len(patterns)
        if score > 0 and (best is None or score > best["confidence"]):
            best = {"vendor": vendor, "os_hint": os_hint, "confidence": score,
                    "platform": platform, "command": command}
    return best or {"vendor": "unknown", "os_hint": None, "confidence": 0.0,
                     "platform": None, "command": None}

Key change from v1: re.MULTILINE is now explicit (v1's anchors would only match at absolute string-start), scoring is keyword-fraction-based rather than a single brittle regex, and each entry now carries the ntc_platform + assumed command needed by §7.2 — or None for vendors you already know have no template, which routes straight to the LLM lane without wasting a parse attempt.

7.2 Deterministic parser (parsers/deterministic.py)

from ntc_templates.parse import parse_output

class NoDeterministicTemplate(Exception):
    pass

def parse_deterministic(platform: str | None, command: str | None, raw_text: str):
    if platform is None or command is None:
        raise NoDeterministicTemplate("fingerprint has no known ntc-templates match")
    try:
        result = parse_output(platform=platform, command=command, data=raw_text)
    except Exception as e:
        raise NoDeterministicTemplate(str(e)) from e
    if not result:
        # parsed successfully but got nothing back — treat as "no real match", not success
        raise NoDeterministicTemplate("empty parse result")
    return result

Every value coming out of this path gets confidence = 1.0 and source_lane = "deterministic". The orchestrator catches NoDeterministicTemplate and falls through to the LLM lane automatically — the routing decision is now "attempt, then fall back," not "predict, then commit," which is more robust against a fingerprint that guessed right on vendor but wrong on command/platform variant.

7.3 Secret redaction (ingestion/redact.py) — NEW in v2

Runs on any text about to leave the process for the LLM lane. Not a security guarantee, but a meaningful reduction of exposure for an enterprise security tool sending customer configs to a third-party API.

import re

REDACTION_PATTERNS = [
    (r"secret \d+ \S+", "secret <REDACTED>"),
    (r"password \d+ \S+", "password <REDACTED>"),
    (r"pre-shared-key \S+", "pre-shared-key <REDACTED>"),
    (r"community \S+", "community <REDACTED>"),
    (r"(api[_-]?key\s*[:=]\s*)\S+", r"\1<REDACTED>"),
]

def redact(raw_text: str) -> str:
    for pattern, replacement in REDACTION_PATTERNS:
        raw_text = re.sub(pattern, replacement, raw_text, flags=re.IGNORECASE)
    return raw_text

7.4 LLM fallback lane (parsers/llm_fallback.py)

import instructor
from anthropic import AsyncAnthropic
from app.models.schema import NormalizedDeviceConfig
from app.ingestion.redact import redact

client = instructor.from_anthropic(AsyncAnthropic())

async def parse_with_llm(vendor: str, raw_config: str, few_shot: list[str] | None = None) -> NormalizedDeviceConfig:
    safe_config = redact(raw_config)
    few_shot_block = ""
    if few_shot:
        few_shot_block = "Examples of correct mappings for this vendor:\n" + "\n".join(few_shot) + "\n\n"
    return await client.messages.create(
        model="claude-opus-5",   # accuracy matters more than latency for extraction + honest confidence
        max_tokens=4000,
        response_model=NormalizedDeviceConfig,
        messages=[{
            "role": "user",
            "content": (
                f"Vendor: {vendor}\n"
                f"{few_shot_block}"
                "Extract every security-relevant setting from this config into the schema. "
                "For every field, quote the EXACT source line you derived it from, and set "
                "confidence honestly — if you are guessing, say so with a low number.\n\n"
                f"{safe_config}"
            ),
        }],
    )

Changes from v1: async client so it doesn't block the FastAPI event loop when called from an async def route; redaction applied before the config text is sent anywhere; corrected model string; few-shot examples are now an explicit parameter rather than assumed to be injected elsewhere. A field routes to the Training UI when confidence < CONFIDENCE_THRESHOLD (start at 0.75, tune from real usage). For bulk uploads, call this with asyncio.gather(*[parse_with_llm(...) for device in batch]) so unknown-vendor files parse concurrently.

7.5 Training UI backend (training/corrections.py)

async def get_few_shot_examples(vendor: str, os_hint: str | None, limit: int = 5):
    return db.exec(
        select(Correction)
        .where(Correction.vendor == vendor, Correction.os_hint == os_hint)
        .order_by(Correction.created_at.desc())
        .limit(limit)
    ).all()

async def submit_correction(correction: CorrectionExample, db):
    db.add(Correction(**correction.model_dump()))
    db.commit()
    # NEW in v2: close the loop — mark the old field superseded, write the corrected value,
    # then re-run the rule engine for every device this correction affects, so
    # `needs_review` findings actually flip to pass/fail without a manual re-trigger.
    affected_devices = get_devices_with_control_area(
        vendor=correction.vendor, os_hint=correction.os_hint,
        control_area=correction.mapped_control_area, db=db,
    )
    for device in affected_devices:
        await reevaluate_device(device.id, db)

7.6 Rule engine (rules/engine.py)

# rules/packs/cis_ios.yaml
- control_id: CIS-1.1.4
  framework: CIS
  control_area: ssh_version
  expected_value: "2"
  severity: high
  remediation_template: "ip ssh version 2"
- control_id: CIS-1.2.1
  framework: CIS
  control_area: telnet_enabled
  expected_value: "false"
  severity: critical
  remediation_template: "no service telnet"

def evaluate(fields: list[SecurityBaselineField], rules: list[ComplianceRule]) -> list[Finding]:
    field_map = {f.control_area: f for f in fields}
    findings = []
    for rule in rules:
        field = field_map.get(rule.control_area)
        if field is None:
            findings.append(Finding(status="needs_review", ...))  # never silently skip
        elif field.confidence < CONFIDENCE_THRESHOLD:
            findings.append(Finding(status="needs_review", ...))
        else:
            status = "pass" if field.value == rule.expected_value else "fail"
            findings.append(Finding(status=status, remediation_cli=rule.remediation_template, ...))
    return findings

7.7 Reporting (reporting/generate.py)

Jinja2 renders templates/report.html with autoescape=True (unescaped config/remediation text containing </> from ACL syntax will otherwise break the HTML) with the device metadata (now including hostname/serial/model/firmware) + findings list, then weasyprint.HTML(string=rendered).write_pdf(...).

8. Sequence flow per lane

Deterministic (Cisco/Juniper): POST /devices/upload → vendor_detect fingerprints as cisco_ios/show running-config with high confidence → parse_deterministic() via ntc-templates succeeds → fields written with confidence=1.0 → POST /devices/{id}/evaluate runs rule engine → GET /report.pdf.

Deterministic attempt fails, falls through (new in v2): Upload → fingerprint guesses cisco_ios but it's actually IOS-XE with a template mismatch → parse_deterministic() raises NoDeterministicTemplate → orchestrator catches it and calls parse_with_llm() instead, same as a vendor with no template at all. No dead end.

LLM fallback (Palo Alto, no template): Upload → vendor_detect recognizes vendor but has no ntc-templates match → config redacted → parse_with_llm() called with no few-shot examples (first time) → fields returned with per-field confidence → all fields ≥ 0.75 → straight to rule engine → report. No human touches this run.

LLM fallback + training (unknown SONiC device): Upload → vendor_detect returns low confidence, os_hint=None → config redacted → parse_with_llm() called → several fields return confidence < 0.75 → those fields appear in GET /training/pending → human calls POST /training/corrections for each → correction stored, old field marked superseded, rule engine re-run automatically on the affected device → next SONiC upload calls get_few_shot_examples() first and injects them into the prompt → confidence on those same fields should now clear the threshold automatically.

10. Dummy data — real sources, 2–3 examples per lane

Rather than hand-writing fake configs from scratch, pull from the actual repositories these vendors/communities publish — the data is realistic, free, and in some cases is literally what the parsing library's own tests run against.

Lane 1 — Purely deterministic (Cisco / Juniper, has an ntc-templates match)

Best source: the ntc-templates repo's own test fixtures — real, anonymized show run / show version outputs used to test the exact library you're integrating. 🔗 https://github.com/networktocode/ntc-templates/tree/master/tests — browse tests/cisco_ios/show_run/ and tests/juniper_junos/

Ready-to-use example 1 — Cisco IOS (minimal show run fragment):

Building configuration...

hostname EDGE-SW01
!
service password-encryption
!
line vty 0 4
 transport input ssh
!
ip ssh version 2
no service telnet
!
username admin privilege 15 secret 5 $1$abc$XyZ...

Ready-to-use example 2 — Juniper Junos (set-style):

system {
    host-name CORE-FW01;
    services {
        ssh {
            protocol-version v2;
        }
    }
}
system {
    login {
        retry-options {
            tries-before-disconnect 3;
        }
    }
}

Lane 2 — LLM fallback (known vendor, no deterministic template)

Best source: PaloAltoNetworks/iron-skillet — Palo Alto's own official GitHub repo of ready-to-load NGFW configs in both XML and set-command format. 🔗 https://github.com/PaloAltoNetworks/iron-skillet → loadable_configs/

Ready-to-use example 1 — Palo Alto (set format fragment):

set deviceconfig system timezone UTC
set deviceconfig system update-server updates.paloaltonetworks.com
set network interface ethernet ethernet1/1 layer3 ip 10.0.0.1/24
set rulebase security rules allow-outbound source any destination any application any action allow log-end yes

Ready-to-use example 2 — FortiOS (config block fragment):

config system global
    set admin-ssh-v1 disable
    set admintimeout 15
end
config system interface
    edit "port1"
        set ip 10.10.10.1 255.255.255.0
        set allowaccess ping https ssh
    next
end

FortiOS CLI reference examples: https://docs.fortinet.com (search "FortiOS CLI reference config system global")

Lane 3 — Human review + LLM fallback (genuinely unrecognized format)

Best source: SONiC's own config_db.json schema documentation and sample configs, straight from the sonic-net/sonic-buildimage repo — a format almost nothing has a hand-built parser for. 🔗 https://github.com/sonic-net/sonic-buildimage — see src/sonic-yang-models/doc/Configuration.md and src/sonic-config-engine/config_samples.py (ships t1/l2/empty preset sample configs) 🔗 https://github.com/sonic-net/SONiC/wiki/Configuration

Ready-to-use example 1 — SONiC config_db.json fragment:

{
    "DEVICE_METADATA": {
        "localhost": {
            "hostname": "sonic-tor01",
            "hwsku": "Accton-AS7326-56X"
        }
    },
    "BGP_NEIGHBOR": {
        "10.0.0.1": {
            "admin_status": "up",
            "asn": "65100",
            "name": "T1-01"
        }
    }
}

Ready-to-use example 2 — MikroTik RouterOS export (.rsc), an equally good "never seen it" case: 🔗 official export docs: https://help.mikrotik.com/docs/spaces/ROS/pages/328155/Configuration+Management

/interface bridge
add name=bridge1
/ip address
add address=10.1.0.1/24 interface=bridge1
/ip service
set telnet disabled=yes
set ssh port=22

Why these two work well as lane-3 examples: neither SONiC's JSON key-value schema nor MikroTik's /path + add/set syntax resembles any Cisco/Juniper template structure at all — a deterministic parser genuinely has nothing to match against, so these are honest tests of the full fallback-plus-training loop, not just a relabeled lane-2 case.

Quick-start order

  1. Stand up Postgres + FastAPI skeleton, wire the devices upload endpoint — include the new identity columns from day one, retrofitting them later means a migration plus a report-template rewrite.
  2. Drop lane-1 fixtures in, get ntc_templates.parse_output returning real structured data via the assumed-command mapping in §7.1/7.2, including the try/except fallback.
  3. Hand-write 3–4 compliance_rules YAML entries and get pass/fail working end to end on lane 1 only — this proves the whole spine before AI enters the picture.
  4. Add the LLM fallback lane with async instructor + redaction + the Pydantic schema, test against lane-2 fixtures.
  5. Add the confidence threshold gate and the corrections table (with the re-evaluate-on-correction trigger), test against lane-3 fixtures.
  6. Wire the PDF report last — it's the least risky part and easiest to leave for the end, but make sure the device identity block and autoescape are in from the first draft of the template.
